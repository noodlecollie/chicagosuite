# chicagosuite

Some C/C++ toolchain experiments to see how far back in the Windows lineage we can easily build applications for. This may or may not go anywhere as a project, depending on how I feel.

## Aim

To take as modern C/C++ code as we can, and compile it using as modern a compiler as we can, to run on as old a machine as we can. Code should be portable and compliant with modern development practices (sorry OpenWatcom), and open-source (less sorry, MSVC).

My pipe dream would be to write some lightweight UI library that can map UI elements to native Windows UI controls, and create a demo application that runs on Windows 95 just as well as it runs on Windows 11. In this case, this repo would serve as an ecosystem, supplying compatibility libraries for missing Windows kernel functions, and toolchain configurations to build applications using CMake.

## Existing Work

This wouldn't even be feasible without the very cool work of the following people:

* Colin Finck, who has written about compiling modern code for [Windows 2000](https://colinfinck.de/posts/modern-visual-studio-meets-ancient-windows/) and [Windows NT 4.0](https://colinfinck.de/posts/targeting-25-years-of-windows-with-visual-studio-2019/).
* Alex313031, who has [built on this idea](https://github.com/Alex313031/libnt5).
* Everyone building and maintaining [LLVM](https://llvm.org/), plus [various](https://github.com/mstorsjo/llvm-mingw) [forks](https://github.com/mon/llvm-mingw-xp).

## Current Status

The page on [compiler investigations](docs/compiler-investigations.md) details what I've been able to experiment with so far. The `hello_world` directory has some tiny demos that I've checked compatibility for with Windows XP in a VM, and `wincompatlib` is my own fork of [EnlyzeWinCompatLib](https://github.com/enlyze/EnlyzeWinCompatLib) that's been adjusted to compile with clang.

Run `distrobox assemble create distrobox.ini && distrobox enter chicagosuite_dev` to create and enter a Distrobox container with all relevant development tools inside.

At some point I'll start adding CMake scaffolding into this repo, but first I need to work out which toolchain I need in order to compile everything here, and then how to actually perform the compilation.

## AI Disclaimer

As an unapologetic generative AI hater, none of the code in this repo is generated by AI. Agents are not welcome here. Why would I delegate the fun part to a machine?

In the interests of transparency, I have found Google's AI search to be useful for questions like "Hey, I had no idea there were different dialects of assembly language, why won't clang parse this .asm file?" I've also found it amenable to questions that would otherwise bring out the worst in the StackOverflow community, such as "Is it possible for me to use clang to compile C++ for Windows 95?", which would usually have elicited no response and 17 downvotes. In all such cases, I limit the AI involvement to throwing up some leads from a hyper-specific query, and follow those leads myself. Again - why would I delegate the fun part to a machine?
